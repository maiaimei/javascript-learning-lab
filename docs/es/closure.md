# JavaScript 闭包 学习笔记

## 一、闭包是什么

> **一句话记忆：闭包 = 函数 + 它能访问的外部变量环境**

⚠️ 容易踩的坑：**闭包 ≠ 函数本身**。函数是闭包的必要组成部分，但闭包是「函数」和它「创建时绑定的词法环境」共同组成的实体。

> MDN 视角：闭包是由**函数**和它创建时所绑定的**周围词法环境**共同组成的实体。

通俗理解：一个函数能访问它外部作用域里的变量，**即使外部函数已经执行完了**。

### 闭包形成的 3 个条件
| 条件 | 说明 |
|------|------|
| 1. 有引用 | 内部函数使用了外部作用域的变量 |
| 2. 被保存 | 内部函数被 `return` 出去 / 塞进定时器 / 挂到事件监听 |
| 3. 不回收 | JS 引擎发现还有人要用这些变量，就不让 GC 回收 |

---

## 二、闭包是怎么形成的

当**函数内部定义了另一个函数**，且**内部函数引用了外部函数的变量**，闭包就形成了。

核心机制：内部函数会“记住”定义时的环境。外部函数执行完毕后，被引用的变量**不会被销毁**，而是继续挂在闭包环境里。

---

## 三、闭包的核心特点

- ✅ **记忆性**：内部函数记住定义时的词法环境
- ✅ **延长生命周期**：外部函数执行完，局部变量依然存活（不被 GC 回收）
- ❌ **滥用有代价**：长期持有引用 → 容易导致内存泄漏
- 💡 不用的闭包引用记得手动置 `null` 释放

---

## 四、闭包有什么用

| 场景 | 说明 |
|------|------|
| 数据封装 / 模拟私有变量 | 外部拿不到 `count`，只能通过返回的方法操作 |
| 事件处理保持状态 | 回调里记住当时的 DOM / 数据 |
| 函数柯里化 | 记住一部分参数，延迟执行 |
| 模块模式 | 早期 ES5 写模块的主流手段 |

## 五、代码示例

```javascript
// ❌ 没有闭包：每次调用都是全新的 count
function normalCounter() {
let count = 0;
return count + 1;
}
normalCounter(); // 1
normalCounter(); // 还是 1

// ✅ 经典闭包：count 被“活下来”了
function makeCounter() {
let count = 0; // 局部变量，按理说函数执行完就没了
return function () {
count++;
return count;
};
}
const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3

// ✅ 这也是闭包（但容易误以为不是）
function outer() {
let a = 1;
function inner() {
console.log(a);
}
inner(); // 此时 outer 还没结束，inner 正在用 a
}
outer();
```

> 📌 补充：`outer` 里的例子**语法上是闭包**，但因为 `inner` 没有被保存出去，外部函数一结束整个环境就没引用了，实际开发中感知不强。**真正“有用”的闭包，一定是内部函数被传递/保存了出去**。

---

## 六、注意事项

1. **不是所有嵌套函数都产生“有效闭包”**，得看内部函数有没有被带出去活下来
2. 循环中用闭包注意 `var` 的陷阱（用 `let` 解决）
3. 定时器 / 事件监听里的闭包，解绑时要清引用，否则内存泄漏
4. 现代框架里（React/Vue）闭包很常见，尤其 `useEffect` 的依赖数组逻辑

---

## 七、速记卡片

> **闭包就是：函数 + 它能访问的外部变量环境的组合**
> 形成：有内部函数 → 引用外部变量 → 被保存出去
> 本质：JS 引擎发现还有人用，就不回收那些变量了 🧠
